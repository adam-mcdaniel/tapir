# Generating wrappers from headers

Writing `interpose!` lines by hand is fine for seven functions. rocBLAS,
cuSOLVER and friends have thousands. `tapir-gen` reads C headers and writes
the declarations for you. It works as a library for `build.rs` and as a
command-line tool.

In this chapter you will replace the hand-written `pix` wrappers with
generated ones.

## Step 1: add the build dependency

`tapir-pix/Cargo.toml`:

```toml
[package]
name = "tapir-pix"
version = "0.1.0"
edition = "2021"

[lib]
crate-type = ["cdylib"]

[dependencies]
tapir = { path = "../tapir/crates/tapir" }

[build-dependencies]
tapir-gen = { path = "../tapir/crates/tapir-gen" }
```

## Step 2: write `build.rs`

`tapir-pix/build.rs`:

```rust
use std::path::PathBuf;

/// How to capture and tag pix parameters: `selector action` per line.
const RULES: &str = "
:enum        @mode
format       @mode
width        @size
height       @size
radius       @radius
path         cstr@path
pix_map.fn   sym
";

fn main() {
    let header = "../pix/pix.h";
    let mut types = tapir_gen::TypeMap::c_basic();
    types.handle("pix_image").enumeration("pix_filter").scalar("pix_int", "i32");

    let mut g = tapir_gen::Generator::new(types);
    g.rules.parse_text(RULES).unwrap();
    g.exclude("pix_bytes");
    g.header(header, "pix", &["PIX_API"]).unwrap();

    let out = PathBuf::from(std::env::var("OUT_DIR").unwrap());
    std::fs::write(out.join("wrappers.rs"), g.render()).unwrap();
    std::fs::write(out.join("report.txt"), g.report()).unwrap();
    println!("cargo:rerun-if-changed={header}");
}
```

Here is what each part does.

### The type map

The generator has to know the ABI of every **by-value** type it sees.
`TypeMap::c_basic()` knows C's built-in types (`int`, `size_t`, `double`,
`int64_t`, `char`, ...). Add the library's own typedefs:

| Method | For | FFI type | Default mode |
|---|---|---|---|
| `.scalar("pix_int", "i32")` | integer and float aliases | the Rust type given | `val` |
| `.enumeration("pix_filter")` | C enums | `i32` | `val` |
| `.handle("pix_image")` | typedefs of a struct pointer | `*mut c_void` | `skip` |

Pointer parameters need no entry. They become `*const c_void` or
`*mut c_void` unless a mode needs the pointee type.

You can also let the generator find typedefs itself:
`types.scan(&header_text)` registers `typedef struct x *h;` as a handle,
`typedef enum {...} e;` as an enum, and `typedef int i;` as the matching
scalar. `tapir-cuda` does this for all of the CUDA headers.

### Rules

Rules choose the capture mode and the tag. Each line is `selector action`:

- The **selector** is a parameter name (`width`), `function.parameter`
  (`pix_map.fn`), a glob (`ld*`, `*_size`), or a C kind instead of a name:
  `:int`, `:float`, `:char`, `:enum`, `:handle`, `:ptr`. Matching ignores
  case.
- The **action** is `[mode][@tag]`: `@size` (tag only, default mode),
  `cstr@path` (mode and tag), or `sym` (mode only).

A rule that names the parameter beats a kind rule. Otherwise the **later**
rule wins, so rules you add after a shared vocabulary override it.

Without any rule, by-value scalars are captured with `val` (`char` with
`chr`), and pointers and handles are skipped. The generator never guesses
that a pointer is a string or a callback: you say so with a rule.

### Selecting functions

`g.header(path, lib, export_macros)` takes every prototype that starts
with one of the export macros (`PIX_API int pix_blur(...)`). Pass `&[]` to
take every top-level prototype. `exclude` and `include` filter by name
glob:

```rust
g.exclude("*_create*");   // never wrap these
g.include("pix_*");       // if any include is given, only wrap matches
```

## Step 3: include the generated code

`tapir-pix/src/lib.rs`:

```rust
//! libtapir_pix.so, with wrappers generated from pix.h.
tapir::preload!(|b| {
    b.default_key("@size:log2; @radius:drop");
    b.from_env("bbv,summary");
});

include!(concat!(env!("OUT_DIR"), "/wrappers.rs"));
```

Build. The generated file is in `target/release/build/tapir-pix-*/out/`:

```rust
// @generated by tapir-gen. Do not edit.
#[allow(unused_imports, non_snake_case)]
mod __tapir_generated {
use ::core::ffi::{c_char, c_void};

::tapir::interpose! {
    lib "pix";
    fn pix_blur(img: *mut c_void => skip, radius: f32 => val "radius") -> i32;
    fn pix_convert(img: *mut c_void => skip, format: c_char => chr "mode") -> i32;
    fn pix_free(img: *mut c_void => skip);
    fn pix_load(path: *const c_char => cstr "path") -> *mut c_void;
    fn pix_map(img: *mut c_void => skip, fn_: *mut c_void => sym) -> i32;
    fn pix_resize(img: *mut c_void => skip, width: i32 => val "size", height: i32 => val "size", filter: i32 => val "mode") -> i32;
    fn pix_save(img: *mut c_void => skip, path: *const c_char => cstr "path") -> i32;
}
}
```

These are the same declarations you wrote by hand, with one change: the C
parameter `fn` is a Rust keyword, so it was renamed `fn_`. Rules still
match the C name (`pix_map.fn`).

The report lists what was skipped and why:

```text
tapir-gen: 7 functions wrapped, 0 skipped
```

Run the application again. The output is the same as in the previous
chapter.

## When something is skipped

The generator skips a function, and reports it, if it cannot wrap it
safely. This happens when a by-value type is unknown, a function is
variadic, a struct is passed by value, or a rule asks for a mode that does
not fit the type. To see this, run the command-line tool without the type
map:

```sh
$ tapir/target/release/tapir-gen --lib pix --export PIX_API --report pix/pix.h > /dev/null
tapir-gen: 0 functions wrapped, 8 skipped
      7 x parameter `pix_image img`: unknown by-value type `pix_image`
      1 x return type: unknown by-value type `pix_image`
```

A mode that does not fit is reported too:

```sh
$ tapir-gen --lib pix --export PIX_API --scan-types --arg 'width=cstr' --report pix/pix.h > /dev/null
tapir-gen: 7 functions wrapped, 1 skipped
      1 x parameter `pix_int width`: mode `cstr` does not fit by-value `pix_int`
```

Check the report whenever you upgrade the wrapped library. Writing it to
`OUT_DIR/report.txt`, as `build.rs` does above, keeps it next to the
generated code.

## The command-line tool

`tapir-gen` takes the same settings as flags. They apply to the headers
that follow them:

```sh
tapir-gen --lib pix --export PIX_API --scan-types \
          --arg ':enum=@mode' --arg 'format=@mode' --arg 'width=@size' --arg 'height=@size' \
          --arg 'radius=@radius' --arg 'path=cstr@path' --arg 'pix_map.fn=sym' \
          --exclude pix_bytes --report pix/pix.h > wrappers.rs
```

Use it to look at what a header would produce, or to generate a file once
and then edit it by hand. Every flag is listed in the
[tapir-gen reference](../reference/tapir-gen.md).

## Headers the parser cannot read

The parser is simple on purpose. It removes comments and preprocessor
lines, then reads `ret name(params);` statements. Most real headers need
one of these:

- **The export macro is not the first word** (`int MYLIB_API f(...)`):
  use `g.source_marked(&text, "mylib", &["MYLIB_API"])`, or `--marker` on
  the command line.
- **Calling-convention macros** (`CUBLASWINAPI`, `__host__`): remove them
  with `g.ignore("CUBLASWINAPI")`, or `--ignore`.
- **Fortran-style bindings** that pass scalars by pointer:
  `g.fortran(true)`, or `--fortran`, reads *tagged* scalar pointers with
  `deref` and `char` pointers with `deref_chr`.
- **Prototypes hidden behind macros**: list the prototypes in a small
  text file and pass it with an empty export list, or write those wrappers
  by hand. Generated and hand-written `interpose!` blocks can live in the
  same crate, as in `tapir-cuda`.
